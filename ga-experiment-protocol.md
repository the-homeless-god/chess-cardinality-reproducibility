# Зафиксированный протокол проверки GA0→GA1→GA2, версия 1

Протокол записан до завершения сбора WDL-ответов и анализа результатов политик.
Он адаптирует **роли** каскада из диссертации: GA2 ищет вектор весов
политики, GA1 выбирает настройки GA2, GA0 ограничивает число оценок и
проверяет раннюю остановку. Это отдельная постановка по отношению к
ранее замороженной модели двух соревнующихся шахматных игроков в
`ga-cascade.md`.

## Данные и разделение

250 заранее выбранных позиций из мартовской базы Lichess 2025: 50
позиций на каждое число фигур 3–7, максимум одна позиция из партии.
Порядок внутри страты определяется SHA-256 от seed, партии и FEN без
использования результата. Первые 30 позиций каждой страты — обучение
(150), следующие 10 — проверка настройки (50), последние 10 —
отложенный тест (50). WDL каждого легального хода известен только
оценщику; при выборе хода алгоритмы получают лишь признаки позиции.

## Признаки и целевая функция

Для легального хода считаются: разность материала после хода;
мобильность соперника `κ`; `K^Σ₂` и `K^U₂` из полученной позиции;
признак шаха; продвижение пешки. Каждый признак нормируется внутри
списка ходов исходной позиции в интервал [−1,1]. `K^V` с точным WDL
**не** является входным признаком: иначе оценка tablebase попала бы в
политику, которую проверяем без оракула. Вектор из шести весов в [-2,2]
задает линейный score; равенства разрешаются лексикографически по UCI.

Оценка хода: win=2, draw=1, loss=0. Пограничные `cursed-win` и
`blessed-loss` считаются ничьей в первичной оценке и показываются
отдельно. Категория хода API дана для следующей стороны; знак
инвертируется. Фитнес — средняя нормированная награда на обучении
относительно максимума среди ходов каждой позиции. На тесте первичный
показатель — доля выборов с максимальной точной категорией; вторичный —
средний regret (разность с лучшим ходом), доля сохранения победы/ничьей
для исходных win/draw, стоимость оценок и время.

## Алгоритмы и бюджет

GA2: популяция из 12 шестимерных векторов, турнирный отбор (размер 3),
арифметический кроссовер, гауссова мутация с отражением границы,
элитизм 2. GA1 выбирает одну из трех заранее заданных конфигураций
`(mutation_sigma, crossover_probability)` = (0.15,0.5), (0.4,0.7),
(0.8,0.9) по проверочной выборке. Каждая получает пилот 120 оценок
фитнеса; остаток бюджета 240 отдается победителю. GA0 ограничивает
общий бюджет 600 оценками. На границе каждого поколения после пилота
останавливает поиск, если проверочная доля оптимальных ходов ≥0.90 и
не растет три поколения подряд. Порог и правило не меняются после
просмотра теста. Конечный вектор выбирается только по проверке.

Сравнение: случайный ход; max/min `κ`, max `K^U₂`, жадный материал,
GA2 с фиксированной средней конфигурацией при 600 оценках,
GA1+GA2 с тем же максимумом 600 без ранней остановки, полный
GA0→GA1→GA2. Случайная политика повторяется для каждого seed;
эволюционные режимы используют 10 заранее заданных seed 100–109.
Все режимы считают время подготовки признаков отдельно от времени
оптимизации. Tablebase-оптимум — только потолок качества.

## Вывод и статистика

Полезность проверяется попарно на одних 50 тестовых позициях: разность
долей оптимальных ходов и regret с 95%-интервалом по bootstrap позиций
(10 000 ресемплов, seed 20261004). Для разных seed сообщаются медиана
и диапазон результатов. При малой выборке вывод ограничивается
наблюдаемой областью реальных 3–7-фигурных позиций этого корпуса;
совпадение с оракулом на позициях с одним исходом всех ходов
показывается отдельно. Дебютный каталог остается описательным.
